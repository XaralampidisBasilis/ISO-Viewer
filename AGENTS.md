# ISOViewer development instructions

- Read [ARCHITECTURE.md](ARCHITECTURE.md) before broad exploration. Start with the relevant entry point and follow its imports, callers, or GLSL includes. Use `rg` within the relevant subtree and read only the sections needed. Batch independent reads and reuse findings from earlier in the session.
- Check the working tree and preserve existing edits. Use `src/` for implementation. Keep generated `docs/` and large `static/` assets out of searches and diffs unless the task concerns them.
- Match nearby conventions. Application code uses ES modules, compute programs use TypeScript with embedded GLSL, and viewer shaders use `.glsl` includes and compile-time defines. Preserve public names, define values, and producer/consumer layouts. Prefer a targeted fix in the active path and reuse existing helpers.
- Use the spacious, Three.js-inspired layout in [AnisotropicDistanceMap.js](src/javascript/Computes/Maps/AnisotropicDistanceMap.js) as the JavaScript style reference. Use four-space indentation, put class, method, and control-flow opening braces on their own lines, and leave blank lines between methods and distinct steps. Use named intermediate values where they make a calculation easier to follow. Keep punctuation and spacing consistent with nearby code and limit formatting edits to the code being changed.
- Preserve nearest-hit correctness, conservative skipping, half-voxel alignment, and the agreement between CPU bounds, GPU maps, and shader traversal. For math changes, check endpoints, near-zero denominators, degenerate polynomials, and axis-parallel or tied face crossings before adjusting tolerances.
- Prefer reducing GPU work, texture fetches, passes, and synchronous readbacks through algorithmic changes. Compare results before timing. Keep shader debug variants out of performance measurements. Compare the same scan, isovalue, camera, viewport, and settings, and measure initialization separately from steady-state rendering.
- Use the [validation commands and diagnostics](ARCHITECTURE.md#validation-and-performance) that match the change. For traversal changes, compare hit/miss, first-hit distance, and residual against the same mode with skipping and box clipping disabled. Exercise affected shader variants in WebGL2 where available.
- Update only affected sections of `ARCHITECTURE.md` when architectural contracts change. Update this file only when development practices change. Report changes, relevant checks and results, and any remaining uncertainty concisely.
